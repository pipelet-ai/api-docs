# MiniMax H3 Video Generation API

This document describes the MiniMax H3 endpoints exposed by `batch/src/routes/fal-routes.ts` under the model id `minimax_h3`.

H3 generates video **with synchronized audio** — dialogue, sound effects, and music come out of the same pass as the picture. One model id covers three task modes:

| Task | What it does | Trigger |
|------|--------------|---------|
| `t2va` (text-to-video) | Generates video + audio from a prompt alone | No media inputs present |
| `fl2va` (image-to-video) | Animates from a first frame and/or toward a last frame | `first_frame_url` / `last_frame_url` present |
| `ref2va` (reference-to-video) | Generates a new scene that keeps subjects, motion, and voices consistent with reference media | Any `reference_*` input present |

The task is inferred from which inputs you send; you can also pin it explicitly with `task` (`t2va`, `fl2va`, or `ref2va`; aliases `text_to_video`, `image_to_video`, `first_last_frame_to_video`, `reference_to_video` are accepted). The modes combine: boundary frames sent **alongside** references stay exact keyframes on a `ref2va` job — see [hybrid frame pinning](#h3-hybrid). The resolved task is echoed back as `task` in the job's inputs, and it decides which workers may pick the job up: each task is its own job template internally (`minimax_h3_t2va_api`, `minimax_h3_fl2va_api`, `minimax_h3_ref2va_api`), so a job only ever lands on a worker that has that task's checkpoint loaded.

Note: All routes require an authenticated request (middleware `requireUser`).

## Base URL

- Production: `https://batch.pipelet.net`

## Endpoints (quick reference)

- Create request: `POST /queue/minimax_h3`
- Check status: `GET /queue/minimax_h3/requests/:requestId/status`
- Cancel request: `PUT /queue/minimax_h3/requests/:requestId/cancel`
- Fetch result: `GET /queue/minimax_h3/requests/:requestId`

### Free tier: `minimax_h3_flash` {#h3-free-tier}

The tier of an H3 job is carried by its queue name. `minimax_h3` is the paid queue; **`minimax_h3_flash`** is the free tier — the same jobs, rendered by the same workers, but scheduled on the free queue with its mandatory per-user wait time and lower priority. Submit to `POST /queue/minimax_h3_flash` to place a job there explicitly.

A request to `minimax_h3` is also moved to `minimax_h3_flash` automatically when either applies:

- the request carries `x-user-subscription: free` (or no subscription header at all), or
- the body's `priority` is below `3`.

In that case the response's `status_url` / `response_url` / `cancel_url` point at `minimax_h3_flash`. Either queue name resolves a job that lives on the other, so polling `/queue/minimax_h3/requests/:id/status` for a re-homed job still works — but prefer the URLs returned with the request.

## Webhook notification

If you want to receive notifications when the job status changes (e.g. `acquired`, `completed`, `failed`), you can attach a webhook to this request.

## 1) Create a request

POST `https://batch.pipelet.net/queue/minimax_h3`

Body: JSON inputs for the model.

### 1.1) Common fields (all tasks)

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `prompt` | string | required | Text prompt. Describe the picture, then the sounds tied to it, then any background music. Spoken lines go in quotation marks. |
| `duration` | number | `5` | Clip length in seconds. **4–30 seconds**; long durations are only available on smaller canvases — see [Duration × resolution limits](#h3-duration-resolution). |
| `short_edge` | integer | `768` | Short edge of the delivered video in pixels. **256–768** (multiple of 32) render natively; **1080** (Full HD) and **2160** (4K) are also accepted and delivered through a built-in FlashVSR upscaling pass. (Alias: `min_height`.) |
| `aspect_ratio` | string | `16:9` (t2va), `auto` (with media) | One of `auto`, `21:9`, `16:9`, `4:3`, `1:1`, `3:4`, `9:16`. `auto` follows the input image. You may send `width`/`height` instead and the ratio is derived. |
| `tier` | string | `turbo` | `turbo` (8 steps, fastest) or `quality` (20 steps, higher fidelity; alias `base`). The step count is fixed by the tier — do not send `steps`. |
| `seed` | integer | `7` | Non-negative integer. The default is fixed, so identical requests reproduce; set your own seed to get variation. |
| `task` | string | inferred | Optional explicit task selector (see table above). |
| `priority` | number | optional | Priority in the queue; the bigger the number, the higher priority. |

Notes:

- **HD output is built in.** H3's native canvas tops out at a 768-pixel short edge (e.g. 1366×768 at 16:9). Requesting `short_edge` 1080 or 2160 renders the clip and finishes it with an in-worker FlashVSR upscale before delivery — the same render-then-upscale approach the official H3 service uses for its 2K/4K tiers. No separate upscale call is needed.
- **Durations up to 30 seconds** are supported end to end (most other video models cap at 10). Duration and canvas share one budget, so the longest clips come on the smaller canvases — see [Duration × resolution limits](#h3-duration-resolution).
- **There is no negative prompt.** Phrase everything positively: instead of "no music", write "Ambient sound only."; instead of "no talking", write "she stays silent".
- **Prompt enrichment** is applied automatically on the server: brief prompts (under 100 characters) are always expanded into a full H3 prompt by a vision LLM; very long, professionally written prompts (800+ characters) are passed through untouched. Send the `x-pipelet-force-enrichment: 1` header to force enrichment regardless of length. Quoted dialogue in your prompt is always preserved character for character.

### Duration × resolution limits {#h3-duration-resolution}

Duration and canvas share **one budget**: the GPU cost of a clip scales with `width × height × seconds`, and the fleet renders combinations up to **18 megapixel-seconds** (measured limit of the production hardware). A request past the budget is rejected at submission with a `400` that names the combination, so nothing is silently shortened or downscaled.

Maximum `duration` (seconds) by `short_edge` and `aspect_ratio`:

| `short_edge` | `1:1` | `4:3` / `3:4` | `16:9` / `9:16` | `21:9` |
|---|---|---|---|---|
| 480 | 30 | 30 | 30 | 30 |
| 544 | 30 | 30 | 30 | 26 |
| 640 | 30 | 30 | 24 | 18 |
| 704 | 30 | 27 | 20 | 15 |
| 768 | 30 | 22 | 17 | 13 |
| 1080 / 2160 (HD, renders at 544 + FlashVSR) | 30 | 30 | 30 | 26 |

Notes:

- **`aspect_ratio: auto`** is admitted at submission whenever a square (`1:1`) canvas of that `short_edge` would fit — the actual canvas comes from your input image, and the worker re-checks it against the same budget before rendering. For long clips with `auto`, keep the input image at `16:9` / `9:16` or squarer (or set the aspect explicitly) so the derived canvas stays inside the table above; a panoramic or ultra-tall image on a long `auto` job fails at render time with a message naming the budget.
- **HD output (`short_edge` 1080 or 2160)** renders at a 544 base and finishes with the built-in FlashVSR pass, so it follows the 544 row — a full 30-second 1080p clip is supported at typical aspects.
- Practical picks: **30s** → `short_edge` ≤ 544 (or 1080/2160 HD); **25s** → up to 544 at any aspect; **20s** → up to 704 at `16:9`/`9:16`; the full 768 canvas → up to 17s at `16:9`.

### 1.2) Text to video {#h3-text-to-video}

Only the common fields — any frame or reference input is rejected for `t2va`.

```json
{
  "prompt": "Live-action cinematic footage. A street violinist plays under warm lamplight as light snow falls, the camera slowly pushing in. The violin carries a slow, wistful melody over the soft hiss of falling snow and distant traffic.",
  "duration": 10,
  "short_edge": 768,
  "aspect_ratio": "16:9"
}
```

Example:

```bash
curl 'https://batch.pipelet.net/queue/minimax_h3' \
  -H 'Content-Type: application/json' \
  -H 'x-user-id: xy728e9er' \
  -H 'Authorization: Bearer <api-key>' \
  -d '{"prompt":"Live-action cinematic footage. A street violinist plays under warm lamplight as light snow falls, the camera slowly pushing in. The violin carries a slow, wistful melody over the soft hiss of falling snow and distant traffic.", "duration": 10, "short_edge": 768, "aspect_ratio": "16:9"}'
```

### 1.3) Image to video (first / last frame) {#h3-image-to-video}

| Field | Type | Description |
|-------|------|-------------|
| `first_frame_url` | string | URL of the image used as the first frame. (Alias: `image_url`.) |
| `last_frame_url` | string | URL of the image used as the last frame. |

At least one of the two is required for `fl2va`. Provide both for first-to-last keyframe generation — describe the **motion that connects them**, not the two images themselves. With `aspect_ratio: "auto"` (the default when an image is present) the output follows the input image's aspect.

Media URLs may use `http`, `https`, `s3`, or `r2` schemes.

```json
{
  "prompt": "She looks up from the letter, smiles, and quietly says, \"I knew you would come.\" Paper rustles in her hands; rain taps on the window behind her.",
  "first_frame_url": "https://resource.pipelet.net/images/reading.jpg",
  "duration": 5,
  "short_edge": 768
}
```

Example:

```bash
curl 'https://batch.pipelet.net/queue/minimax_h3' \
  -H 'Content-Type: application/json' \
  -H 'x-user-id: xy728e9er' \
  -H 'Authorization: Bearer <api-key>' \
  -d '{"first_frame_url":"https://resource.pipelet.net/images/reading.jpg", "prompt":"She looks up from the letter, smiles, and quietly says, \"I knew you would come.\" Paper rustles in her hands; rain taps on the window behind her.", "duration": 5}'
```

### 1.4) Reference to video {#h3-reference-to-video}

Reference-to-video generates a **new** scene while keeping subjects, motion style, and voices consistent with the reference media you attach. Unlike `fl2va`, the references are not frames of the output — they condition *who and what* appears, and the scene is free to be somewhere the references never showed.

| Field | Type | Limit | Description |
|-------|------|-------|-------------|
| `reference_image_urls` | string[] | **up to 5 images** | Subject/identity references, in order. |
| `reference_video_url` | string | **1 clip** | Motion/appearance reference video. |
| `reference_audio_urls` | string[] | **up to 3 tracks** | Voice references — each conditions the timbre of a voice. What is *said* still comes from the prompt. |

- At least one reference input is required.
- Refer to the assets in your prompt **by modality and list order**: `Image 1` … `Image 5`, `Video 1`, `Audio 1` … `Audio 3`. Example: *"Image 1 is the woman, Image 2 is her dog. Keep both consistent with their references as they walk through a sunlit garden."*
- Restate each subject's fixed identity traits in words (hair, eyes, signature garment) even though they are in the image — this is what holds identity across the clip.
- `ref2va` renders at the default `short_edge` of 768; leave `short_edge` unset.
- Compatibility middle-frame fields (`middle_frame1_url`…`middle_frame3_url`, `second_image_url`, `third_image_url`) are accepted and folded into `reference_image_urls` in order, but the explicit list is preferred. `first_frame_url` / `last_frame_url` sent **without** any reference input are folded the same way; sent **alongside** references they become exact keyframes — see below.

#### Pinning exact first/last frames with references (hybrid) {#h3-hybrid}

Send `first_frame_url` and/or `last_frame_url` **together with at least one reference input** and the boundary images are honored exactly, `fl2va`-style: the clip opens on the first image and/or ends on the last one, while the references keep conditioning identity and voice. This combination is unique to Pipelet — the upstream MiniMax API rejects it.

```json
{
  "prompt": "The clip opens exactly on the first frame: the woman from Image 1 mid-stride on a moonlit beach. She keeps walking toward the camera and says, \"Almost home.\" in the voice from Audio 1. Waves hiss over the sand.",
  "first_frame_url": "https://resource.pipelet.net/images/beach-start.jpg",
  "reference_image_urls": ["https://resource.pipelet.net/images/woman.jpg"],
  "reference_audio_urls": ["https://resource.pipelet.net/audio/voice.wav"],
  "duration": 5
}
```

- **The prompt must describe a scene that starts at the pinned frame.** A prompt that contradicts the image (a different location, pose, or framing) overrides the pin — the model renders the prompt's scene and the boundary image is ignored or dissolves away. Open the prompt by describing what the first image actually shows.
- A pinned last frame works the same way: describe the motion that carries the scene *into* that picture.
- Boundary images should match the output aspect ratio; mismatched images are center-cropped.

```json
{
  "prompt": "Image 1 is a young woman with short black hair and a red scarf. Image 2 is her golden retriever. Audio 1 is her voice. She kneels to greet the dog in a sunlit park, laughs, and says, \"There you are!\" in the voice from Audio 1. The dog's tail thumps against the grass; birdsong carries from the trees.",
  "reference_image_urls": [
    "https://resource.pipelet.net/images/woman.jpg",
    "https://resource.pipelet.net/images/dog.jpg"
  ],
  "reference_audio_urls": ["https://resource.pipelet.net/audio/voice.wav"],
  "duration": 8
}
```

Example:

```bash
curl 'https://batch.pipelet.net/queue/minimax_h3' \
  -H 'Content-Type: application/json' \
  -H 'x-user-id: xy728e9er' \
  -H 'Authorization: Bearer <api-key>' \
  -d '{"prompt":"Image 1 is a young woman with short black hair and a red scarf. Image 2 is her golden retriever. Audio 1 is her voice. She kneels to greet the dog in a sunlit park, laughs, and says, \"There you are!\" in the voice from Audio 1. The dog'\''s tail thumps against the grass; birdsong carries from the trees.", "reference_image_urls":["https://resource.pipelet.net/images/woman.jpg","https://resource.pipelet.net/images/dog.jpg"], "reference_audio_urls":["https://resource.pipelet.net/audio/voice.wav"], "duration": 8}'
```

Example response (all tasks):

```json

  "response_url": "https://batch.pipelet.net/queue/minimax_h3/requests/12",
  "status_url": "https://batch.pipelet.net/queue/minimax_h3/requests/12/status",

}
```

## 3) Fetch the result

GET `https://batch.pipelet.net/queue/minimax_h3/requests/:requestId`

When the job `status` becomes `COMPLETED`, fetch the result from the `response_url`:

```bash
curl 'https://batch.pipelet.net/queue/minimax_h3/requests/12' \

```

## 4) Prompting tips

H3 writes the picture **and** the soundtrack from the same prompt; a prompt that only describes what is visible gets arbitrary audio. In one continuous prose paragraph:

1. Establish the scene (open with the medium: "Live-action cinematic footage.", "Anime.").
2. Describe observable action — what the body does, in order.
3. Direct the camera in prose ("the camera gently tracks right"), not as metadata.
4. Put spoken lines in quotation marks with delivery notes, and budget ~3 words per second of clip.
5. Name the diegetic sounds and tie each to its on-screen source.
6. Add non-diegetic music last, by instrumentation and tempo — or end with "Ambient sound only." to disable it.

Avoid: negations ("no music" — phrase positively instead), mood words in place of physical description, legible on-screen text, and more dialogue than the duration can hold.

## 5) Mapping from fal.ai's minimax/h3 API

If you are porting from [fal's minimax/h3 endpoints](https://fal.ai/models/minimax/h3/text-to-video/api):

| fal parameter | Here |
|---------------|------|
| separate endpoints (`text-to-video`, `image-to-video`, `reference-to-video`) | one model id `minimax_h3`; task inferred or set via `task` |
| `resolution` (`480P`/`768P`/`2K`/`4K`) | `short_edge` in pixels: 256–768 native, 1080/2160 via a built-in FlashVSR finishing pass (the same upscale-a-smaller-base approach as fal's 2K/4K) |
| `image_url` / `end_image_url` | `first_frame_url` / `last_frame_url` (`image_url` also accepted) |
| `reference_image_urls` (≤9) | `reference_image_urls` (≤5) |
| `reference_video_urls` (≤3 clips) | `reference_video_url` (1 clip) |
| `reference_audio_urls` (≤3) | `reference_audio_urls` (≤3) |
| `aspect_ratio` (`adaptive`, …) | `aspect_ratio` (`auto`, …) |
| `enable_prompt_expansion` / `prompt_expansion_mode` | automatic server-side enrichment; force with the `x-pipelet-force-enrichment` header |
| `seed` (random default) | `seed` (fixed default `7` — set your own for variation) |
| `duration` (5–15 s) | `duration` (4–30 s, canvas-dependent — see [Duration × resolution limits](#h3-duration-resolution)) |
